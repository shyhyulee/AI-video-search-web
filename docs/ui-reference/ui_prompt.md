# 一、產品目標

本產品的核心價值是：

> 使用者輸入自然語言後，能在大量影片中快速找到最相關的影片與精準時間片段，並直接播放結果。

UI 必須讓以下流程清楚、快速且容易展示：

```text
新增影片
→ 分析影片
→ 搜尋影片內容
→ 查看相關片段
→ 播放指定時間
```

本次任務只改善 UI/UX、版面結構、狀態呈現與互動體驗，不修改以下核心邏輯：

* yt-dlp 影片下載
* FFmpeg 影片處理
* ASR 字幕產生
* VLM 畫面分析
* Embedding
* Vector Search
* Score Fusion
* Database Schema
* API 呼叫格式
* CSV 匯出格式
* 既有搜尋結果內容

目前畫面包含 YouTube 網址、下載進度及未分析影片列表。請重新排列成以下結構。

## A. 新增影片卡片

標題：

```text
新增影片
```

內容：

```text

[貼上 YouTube 影片網址____________________________] [下載影片]
```

改善要求：

* `選擇本機影片`為 Secondary Button。

* 網址輸入框支援 Enter 執行下載。
* 下載中禁用重複操作。
* 顯示影片名稱、下載百分比、速度及預估剩餘時間。
* 完成後不要顯示英文 `Downloaded:`，改為成功訊息：

```text
✓ 影片下載完成，已加入待分析清單
```

## B. 待分析影片列表

標題：

```text
待分析影片（1）
```

欄位：

```text

```

每一筆操作：

```text

```

支援多選時提供：

```text

```

Empty State：

```text
目前沒有待分析影片
可貼上 YouTube 網址或選擇本機影片
```

要求：

* 影片名稱過長時顯示省略號，Hover 或詳細區顯示完整名稱。
* `10:22`保留為易讀時間格式。
* 日期顯示為 `2026/08/15 08:24`。
* 避免只有一筆資料卻留下大片無意義空白。
* 分析中顯示目前 Pipeline 階段：

```text

建立向量
```

## 搜尋區

* 移除目前右側狹窄的 Chat Search。
* 搜尋框移到影片庫頁面頂部，橫跨主要內容寬度。
* Placeholder：

```text

```

## 影片清單

欄位：


* 選取列使用柔和強調色，不使用過深的藍灰色造成文字對比不足。
* 避免影片名稱因欄寬不足而無法判斷內容。
* 提供 Filter：


## 詳細資訊

* 是否包含音訊、語音、字幕及 OCR。

* 支援鍵盤 Enter 播放選取結果。
* 保留目前「單擊看字幕、雙擊播放」功能，但以畫面文字提示清楚說明。

# 九、Responsive 與 Tkinter 實作要求

* 優先使用 `ttk`。
* 若現有專案已使用 `ttkbootstrap`，可以沿用。
* 未經確認不要引入 CustomTkinter 或改寫成 Web UI。
* 使用可重用的 Style Definition，不要在每個 Widget 分散設定顏色。
* 使用 `grid` 配合 `rowconfigure`、`columnconfigure`、`weight`。
* 同一個 Parent 不混用 `grid` 與 `pack`。
* 使用 `ttk.PanedWindow` 建立可拖曳的左右版面。
* 視窗縮放時：

  * 搜尋框優先水平延展。
  * 影片名稱與描述欄優先延展。
  * 表格取得主要垂直空間。
  * 操作按鈕保持最小可用寬度。
* 支援至少：

  * 1366×768
  * 1920×1080
* 下載、分析、搜尋與 API Retry 不得阻塞 Tkinter Main Thread。
* UI 更新必須安全地回到 Tkinter Main Thread。
* 將視覺樣式、Widget 建立與業務事件處理適度分離，但不要過度設計架構。
